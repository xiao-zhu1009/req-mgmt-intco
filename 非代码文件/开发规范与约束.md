# 开发规范与约束

## 一、技术栈

- 前端：Vue 2 + Element UI
- 后端：FastAPI

## 二、依赖安装规则

允许根据开发需要自行安装依赖，但在执行安装前必须先向用户说明：

- 依赖名称和版本
- 安装原因
- 对项目的影响

获得用户同意后才能执行安装。

## 三、数据库修改规则

允许修改数据库结构或数据，但修改前必须先向用户说明：

- 修改内容
- 修改原因
- 影响范围
- 是否需要迁移或回滚方案

获得用户同意后才能执行数据库修改。

## 四、每次需求的开发流程

1. 读取本规范和项目构思文档。
2. 分析需求、影响范围和现有代码结构。
3. 判断是否需要安装依赖或修改数据库。
4. 如果涉及依赖安装或数据库修改，先向用户申请并说明原因。
5. 在获得许可后实施开发。
6. 运行必要的测试和检查。
7. 汇报修改内容、验证结果和遗留问题。

## 五、默认执行原则

- 保持现有功能正常，不进行无关重构。
- 优先采用项目已有的技术和依赖。
- 代码、配置和文档按目录职责分离。
- 对不确定的需求先说明假设和影响，再开始实施。
- 删除文件、删除数据或进行不可逆操作前必须获得用户明确确认。

## 六、开发记录要求

- 每完成一个可记录的开发需求，必须在 `开发记录.md` 中新增一条记录。
- 每条记录必须标记精确到分钟的开发时间，时间格式为 `YYYY-MM-DD HH:mm`，不得只记录日期。
- 不同日期的开发记录必须使用 `#### YYYY-MM-DD` 标题进行分隔，同一天的记录归入同一个日期标题下。
- 记录至少包含需求名称、状态、需求说明、实现内容、涉及文件和验证结果。
- 未完成项或遗留问题必须明确记录，确保后续可以追溯。
